ここは配布専用リポジトリです。ダウンロードリンク、画像、動作が食い違わないよう、**アプリのすべての変更は、更新したインストーラー Release と対応するドキュメントとともに出荷しなければなりません**。

<a name="required-release-checklist"></a>
## 必須のリリースチェックリスト

1. 非公開の作業ツリーでアプリをビルド/テストします。そのソースツリーをこのリポジトリにコピー/プッシュしないでください。
2. アプリ/インストーラーのバージョンを上げます。`v1.6.2` などの新しい不変タグを使い、古いリリースの実行ファイルを異なるバイト列で置き換えないでください。
3. **最終テスト済みインストーラー**の SHA-256 とサイズを計算します。
4. `release.json`、`SHA256SUMS.txt`、`install.ps1` に固定したバージョン/ハッシュを更新します。
5. README とインストールコマンド、関連する使用方法/設定/トラブルシューティング、CHANGELOG を 8 言語すべてで更新します。メイン README は英語のままにし、国旗リンクで `README.pt-BR.md`、`README.es.md`、`README.zh-CN.md`、`README.fr.md`、`README.ja.md`、`README.hi.md`、`README.ar.md` にリンクします。翻訳ガイドは対応する `docs/<locale>/` に置きます。コマンド、ハッシュ、ファイル名、モデル識別子、API 列挙値を翻訳しないでください。
6. 新パッケージから変更の影響を受ける画面を、合成の非機密データで 8 言語すべて撮影します。英語画像は `docs/images/`、他言語は `docs/images/<locale>/` に置きます。各図解ガイドを更新し、`release.json` の `screenshotsVersion` をアプリバージョンに設定します。実際の Power BI リボンの原画像はポルトガル語のままにし、誤った言語表示に変更せず、その旨を説明してください。実際のモデル名/データや資格情報が写る画像を公開してはいけません。
7. 追跡対象ファイルの厳密な許可リストを確認します。許可内容はドキュメント、PNG スクリーンショット、インストール補助スクリプト/設定、配布検証です。アプリソース、プロジェクトファイル、モデルファイル、資格情報、開発依存関係は含めません。
8. 配布検証をローカルで実行します。アカウントがホスト実行を使用できる場合、GitHub Actions でも許可リスト/メタデータを検証します。
9. 配布専用の変更をコミット/プッシュし、新インストーラー、チェックサム、補助スクリプトを添付した**ドラフト** Release を作成します。
10. アップロードした添付ファイルのサイズ/ハッシュをローカルインストーラーと比較してから、最新リリースとして公開します。
    組み込み更新プログラムは、バージョンが一致する EXE が `uploaded` 状態で、正かつ上限内のサイズを持ち、GitHub の `sha256:` ダイジェストを備えることを要求します。これらの検査を省略したり、プレリリース/ドラフトを安定更新チャンネルとして公開したりしないでください。
11. 資格情報なしで、公開のバージョン付き補助スクリプトを `-DownloadOnly` でテストします。完了を告知する前に結果の SHA-256 と最新リリース URL を検証します。
12. 8 言語すべての言語セレクター、ローカルリンク/見出しアンカー、翻訳版 PNG を検証します。ドキュメントのみの翻訳は、インストーラーのバイト列変更や新しいアプリバージョン作成なしで `main` に公開できます。既存のリリースタグを移動しないでください。

エンドユーザーは **Release の添付ファイル**から EXE をダウンロードします。大きなインストーラーバイナリは Git ツリーに入れません。自動生成ソースアーカイブに含まれるのは配布リポジトリのみで、アプリのソースではありません。

旧リリースとバージョン固定の補助スクリプト URL を保持してください。`releases/latest` は新しい訪問者を現在のリリースへ案内し、古いバージョン付きコマンドは意図的に元のバージョンを維持します。

<a name="if-hosted-validation-is-unavailable"></a>
## ホストされた検証が使えない場合

GitHub Actions のジョブが成功したと主張しないでください。同じ PowerShell 検証をローカルで実行し、ホストランナーの制限を正直に報告して、ワークフローを今後のために保持してください。ホストランナーの制限だけでは公開 Release 添付ファイルのダウンロードは妨げられません。
