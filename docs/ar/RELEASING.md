هذا مستودع للتوزيع فقط. **يجب أن يصاحب كل تعديل للتطبيق إصدار Release بمثبّت محدّث ووثائق مقابلة** كي لا تنحرف روابط التنزيل ولقطات الشاشة والسلوك عن بعضها.

<a name="required-release-checklist"></a>
## قائمة التحقق المطلوبة للإصدار

1. أنشئ التطبيق واختبره في شجرة عمله الخاصة. لا تنسخ شجرة المصدر هذه إلى المستودع ولا تدفعها إليه أبداً.
2. زد إصدار التطبيق/المثبّت. استخدم وسمًا جديداً غير قابل للتغيير مثل `v1.6.2`؛ ولا تستبدل ملفاً تنفيذياً في إصدار قديم بملف ذي بايتات مختلفة.
3. احسب SHA-256 وحجم **المثبّت النهائي الذي تم اختباره**.
4. حدّث `release.json` و`SHA256SUMS.txt` والإصدار/التجزئة المثبتين في `install.ps1`.
5. حدّث README وأوامر التثبيت وتعليمات الاستخدام/الإعداد/استكشاف الأخطاء ذات الصلة وCHANGELOG بجميع لغات الوثائق الثماني. أبقِ README الإنجليزية رئيسية، مع روابط الأعلام إلى `README.pt-BR.md` و`README.es.md` و`README.zh-CN.md` و`README.fr.md` و`README.ja.md` و`README.hi.md` و`README.ar.md`. توجد الأدلة المحلية في مجلد `docs/<locale>/` المطابق. لا تترجم الأوامر أو قيم التحقق أو أسماء الملفات أو معرّفات النماذج أو قيم API enum.
6. التقط شاشات التطبيق المتأثرة من الحزمة الجديدة باللغات الثماني وببيانات اصطناعية غير سرية. توجد الصور الإنجليزية في `docs/images/`، والصور باللغات الأخرى في `docs/images/<locale>/`. حدّث كل دليل مصور واجعل `screenshotsVersion` في `release.json` مطابقاً لإصدار التطبيق. تبقى صورة شريط Power BI الحقيقية باللغة البرتغالية؛ اشرح ذلك ولا تنسب إليها لغة أخرى. لا تنشر أبداً أسماء/بيانات نماذج حقيقية أو لقطات تكشف بيانات اعتماد.
7. راجع القائمة الدقيقة للملفات المسموح بتتبعها. المحتوى المسموح: الوثائق وملفات PNG للقطات الشاشة ومساعد/إعدادات التثبيت والتحقق من التوزيع. لا تشمل الشيفرة المصدرية للتطبيق أو ملفات المشروع أو النماذج أو بيانات الاعتماد أو تبعيات المطورين.
8. شغّل التحقق من التوزيع محلياً. يتحقق GitHub Actions أيضاً من القائمة/البيانات الوصفية عند توفر التنفيذ المستضاف للحساب.
9. اعتمد/ادفع تغييرات التوزيع فقط وأنشئ Release **مسودة** تتضمن المثبّت الجديد وقيمة التحقق والمساعد كملفات مرفقة.
10. قارن حجم/تجزئة الملف المرفوع بالمثبّت المحلي ثم انشره كأحدث إصدار. يتطلب المحدّث المضمّن ملف EXE مطابقاً ذا إصدار محدد وحالة `uploaded` وحجم موجب ومحدود وبصمة GitHub `sha256:`. لا تتخط هذه الفحوص ولا تنشر prerelease/draft على قناة التحديث المستقرة.
11. اختبر المساعد العام المثبّت على إصدار محدد باستخدام `-DownloadOnly` دون بيانات اعتماد. تحقق من SHA-256 وعنوان أحدث إصدار قبل إعلان الإكمال.
12. تحقق من محددات اللغات الثماني والروابط/مراسي العناوين المحلية وصور PNG المحلية. يمكن نشر ترجمات الوثائق فقط على `main` دون تغيير بايتات المثبّت أو إنشاء إصدار تطبيق جديد؛ ولا تنقل وسم Release موجوداً أبداً.

ينزّل المستخدمون النهائيون EXE من **Release assets**. لا تنتمي ملفات المثبّت الثنائية الكبيرة إلى Git tree. لا تتضمن أرشيفات المصدر التلقائية إلا مستودع التوزيع، وليس مصدر التطبيق.

أبقِ الإصدارات القديمة وعناوين المساعد المثبتة على إصدار متاحة. يوجّه `releases/latest` الزوار الجدد إلى الإصدار الحالي؛ وتظل أوامر الإصدارات القديمة المثبتة تثبّت إصدارها الأصلي عمداً.

<a name="if-hosted-validation-is-unavailable"></a>
## إذا لم يتوفر التحقق المستضاف

لا تدّع نجاح مهمة GitHub Actions. شغّل خطوة التحقق نفسها باستخدام PowerShell محلياً، واذكر قيد المشغّل المستضاف بصدق، واحتفظ بسير العمل لاستخدامه لاحقاً. لا يمنع قيد المشغّل المستضاف وحده تنزيل ملفات Release العامة.
