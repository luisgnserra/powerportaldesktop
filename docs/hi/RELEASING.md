[होम पर लौटें](../../README.hi.md)

यह केवल-वितरण रिपॉज़िटरी है। **अनुप्रयोग के हर बदलाव के साथ अद्यतन इंस्टॉलर Release और संबंधित दस्तावेज़ जारी होने चाहिए**, ताकि डाउनलोड लिंक, स्क्रीनशॉट और व्यवहार में अंतर न आए।

<a name="required-release-checklist"></a>
## रिलीज़ की आवश्यक जाँचसूची

1. अनुप्रयोग को उसके निजी कार्य-वृक्ष में बनाएँ/जाँचें। उस स्रोत-वृक्ष को इस रिपॉज़िटरी में कभी कॉपी या push न करें।
2. अनुप्रयोग/इंस्टॉलर संस्करण बढ़ाएँ। `v1.6.2` जैसा नया अपरिवर्तनीय tag उपयोग करें; पुरानी रिलीज़ के निष्पादन योग्य को अलग bytes से प्रतिस्थापित न करें।
3. **अंतिम जाँचे इंस्टॉलर** का SHA-256 और आकार निकालें।
4. `release.json`, `SHA256SUMS.txt` और `install.ps1` में पिन किया संस्करण/हैश अपडेट करें।
5. README और स्थापना आदेश, संबंधित उपयोग/कॉन्फ़िगरेशन/समस्या-निवारण निर्देश तथा CHANGELOG, सभी आठ दस्तावेज़ भाषाओं में अपडेट करें। अंग्रेज़ी मुख्य README रहे; झंडों के लिंक `README.pt-BR.md`, `README.es.md`, `README.zh-CN.md`, `README.fr.md`, `README.ja.md`, `README.hi.md` और `README.ar.md` तक हों। स्थानीयकृत मार्गदर्शिकाएँ संबंधित `docs/<locale>/` फ़ोल्डर में रहती हैं। आदेश, हैश, फ़ाइल नाम, मॉडल पहचानकर्ता या API enum मानों का अनुवाद न करें।
6. नए पैकेज से प्रभावित अनुप्रयोग स्क्रीन सभी आठ भाषाओं में सिंथेटिक, गैर-गोपनीय डेटा से लें। अंग्रेज़ी चित्र `docs/images/` में और अन्य भाषाओं के चित्र `docs/images/<locale>/` में रहें। चित्रित हर मार्गदर्शिका अपडेट करें और `release.json` में `screenshotsVersion` को अनुप्रयोग संस्करण पर सेट करें। असली Power BI रिबन चित्र पुर्तगाली में ही रहता है; इसका सही स्पष्टीकरण दें। वास्तविक मॉडल नाम/डेटा या क्रेडेंशियल दिखाने वाले स्क्रीनशॉट कभी प्रकाशित न करें।
7. सटीक ट्रैक की गई फ़ाइलों की अनुमत सूची जाँचें। अनुमत सामग्री: दस्तावेज़, स्क्रीनशॉट PNG, स्थापना सहायक/कॉन्फ़िगरेशन और वितरण सत्यापन। अनुप्रयोग स्रोत, प्रोजेक्ट फ़ाइल, मॉडल फ़ाइल, क्रेडेंशियल या डेवलपर निर्भरता नहीं।
8. वितरण सत्यापन स्थानीय रूप से चलाएँ। खाते के लिए hosted execution उपलब्ध होने पर GitHub Actions भी अनुमति-सूची/मेटाडेटा जाँचता है।
9. वितरण-सीमित बदलाव commit/push करें और नए इंस्टॉलर, चेकसम तथा सहायक को सामग्री बनाकर Release में जोड़ें।
10. अपलोड सामग्री का आकार/हैश स्थानीय इंस्टॉलर से तुलना करके फिर नवीनतम रिलीज़ प्रकाशित करें। अंतर्निहित updater को संस्करणयुक्त मेल खाती EXE asset का `uploaded` state, धनात्मक सीमित आकार और GitHub `sha256:` digest चाहिए। ये जाँच न छोड़ें और prerelease/draft को स्थिर अपडेट चैनल पर प्रकाशित न करें।
11. सार्वजनिक संस्करण-पिन सहायक को बिना क्रेडेंशियल `-DownloadOnly` से जाँचें। पूर्णता की घोषणा से पहले SHA-256 और latest-release URL सत्यापित करें।
12. सभी आठ भाषा चयनकर्ताओं, स्थानीय लिंक/heading anchor और स्थानीयकृत PNG जाँचें। दस्तावेज़-अनुवाद मात्र को `main` पर प्रकाशित किया जा सकता है, बिना installer bytes बदले या अनुप्रयोग संस्करण बनाए; मौजूदा Release tag कभी न बदलें।

अंतिम उपयोगकर्ता EXE **Release assets** से डाउनलोड करते हैं। बड़े इंस्टॉलर बाइनरी Git tree में नहीं होने चाहिए। स्वचालित source archive में केवल वितरण रिपॉज़िटरी होती है, अनुप्रयोग स्रोत नहीं।

पुरानी रिलीज़ और संस्करण-पिन सहायक URL उपलब्ध रखें। `releases/latest` नए आगंतुक को वर्तमान रिलीज़ तक भेजता है; पुराने संस्करण वाले आदेश जानबूझकर अपना मूल संस्करण ही इंस्टॉल करते हैं।

<a name="if-hosted-validation-is-unavailable"></a>
## यदि hosted सत्यापन उपलब्ध न हो

यह दावा न करें कि GitHub Actions job सफल हुआ। वही PowerShell सत्यापन चरण स्थानीय रूप से चलाएँ, hosted-runner प्रतिबंध ईमानदारी से बताएँ और workflow को बाद के लिए रखें। hosted-runner प्रतिबंध अपने-आप सार्वजनिक Release सामग्री डाउनलोड करने से नहीं रोकता।
